# 单点登录（身份集成里的 OIDC SSO 应用）

每个项目在集成平台建一个自己的 SSO 应用，走 OIDC 授权码加 PKCE。下面是在真实租户里跑出来的结论。

飞书定价页把单点登录列在旗舰版里。先在控制台确认租户有这个模块。

## 在控制台建应用

1. 进集成平台默认是「业务集成」。点侧栏左下角的九宫格图标，切到「身份集成」。无障碍树里找不到这几个字，只能点图标。（实测）
2. 单点登录首页顶部三个页签：「应用管理 / 应用访问控制 / 角色管理」。「新建应用」在右上角。地址形状：列表 `/console/identity/sso-app-manager`，新建 `/custom/create`，详情 `/custom/<App ID>?tabs=config`（配置）或 `?tabs=control`（访问授权），加 `&edit=true` 进编辑态。（实测）
3. 点「新建应用」弹出一排卡片，只点左上角第一张「+ 新建自建应用」。其余是 Canva、Zabbix 等第三方模板。（实测）
4. 「基本配置」只填名称和描述。建出来的应用默认停用，启用开关在「应用配置」页右上角。（实测）
5. 填好登录回调地址后，点「展开配置 / 更多配置」，下面这些都藏在里面。（实测）
   - Scope 默认只勾 profile。加勾 **email** 和 **offline_access**。不勾 offline_access 就没有 refresh_token。
   - 「换取 Token 身份验证方式」默认 `client_secret_post`。代码用 HTTP Basic 的话改成 `client_secret_basic`。
   - ID Token 签名算法保持 **RS256**。「对 ID Token 加密」保持关。
   - 默认有效期：授权码 600 秒，ID Token 3600 秒，Access Token 7200 秒，Refresh Token 30 天。
6. 底部「保存配置」和「保存并启用」。先只点保存配置，访问授权配好再启用。一启用，范围内的人就能登了。
7. 「访问授权」分「企业内访问控制」和「关联组织访问控制」。企业内默认本企业全员可访问，有「可访问成员 / 禁止访问成员」两个子页签。敏感项目用「可访问成员」单独限人。
8. 加关联组织：「添加关联组织」→ 选组织 →「全部成员」→「添加」→ 打开「关联组织访问」开关 → 在提示上确认。提示说的是两个企业的用户要分开认，代码按 company_code 加 sub 认人就没问题。（实测）
9. 「禁止访问成员」只能选部门和成员，不能选用户组。（实测）
10. 想知道一个人能进哪些应用，去「应用访问控制」页签按人搜。（实测）
11. App Secret 旁边的 👁 显示明文，↻ 重置密钥。截图前别点 👁。

## 端点

issuer 是 `https://anycross.feishu.cn/sso/<企业代码>`。其他端点以服务发现文档为准。（实测）

- 授权 `/oidc/auth`，换令牌 `/oidc/token`，用户信息 `/oidc/userinfo`，撤销 `/oidc/revoke`
- 公钥 `/.well-known/jwks.json`，服务发现 `/.well-known/openid-configuration`
- 没有 `end_session_endpoint`，也没有 back-channel logout。不存在一处退出处处退出，每个项目只能退出自己的会话。（实测加文档）

## 协议行为

- 服务发现声明支持 HS256 和 RS256。校验时把算法钉死为 RS256。（实测）
- JWKS 里只有一把 1024 位 RSA 公钥。Go 的 go-oidc 能验。Node 的 openid-client@6 打开验签会拒绝 2048 位以下的公钥，默认又不验令牌端点返回的 id_token。用 `node:crypto` 自己验。换库前先确认它接受 1024 位 RSA。（实测）
- `client_secret_basic` 可用。不带凭据得到 `invalid_client`。（实测）
- PKCE 必须用 S256。verifier 错或不带都被拒。（实测）
- **同一个授权码换第二次会被拒，而且第一次换到的令牌也一起作废。** 回调里绝不能重试换码，换完立刻跳走。曾因为在正常登录里顺手做重放测试，把自己的会话弄坏了。（实测）
- `sub` 就是 union_id。同一个人在主企业和关联组织里是两个 sub，两边 `iss` 一样。按 `company_code` 加 `sub` 认人。（实测）
- 关联组织账号的邮箱是空的，不能拿邮箱认人。（实测）
- 刷新返回新 refresh_token，旧的仍能用。这和飞书开放平台不同。只存最新一枚，退出和踢人时主动撤销。（实测）
- 刷新后上一个 access_token 立刻 401。刷新不返回 id_token，身份信息只在登录时给一次。（实测）
- 撤销接口对真令牌返回 200，之后 refresh_token 立即失效。对假令牌也返回 200。（实测）
- 电脑浏览器里飞书网页登着时零点击登录。飞书 iOS 客户端内也是零点击，约 1.7 秒。（实测）

## 停用与下线

- **判断一个人还能不能用，必须调用户信息接口。** 加进「禁止访问成员」后，刷新照样成功，只有用户信息返回 **403**。加进和移出都在约 1 分钟内生效。（实测）
- 第一轮测试只看了刷新，得出「停用挡不住已登录的人」，这是错的。先确认测对了层，再下结论。
- 建议的项目侧规则：会话放服务端。每 5 分钟用 refresh 换 access_token 再调用户信息。403 立刻下线并撤销令牌。refresh 返回任何 4xx 也下线。用户信息 401 先看是不是别的实例刚刷新过。超时或 5xx 时普通接口最多再放行 15 分钟，敏感接口不放行。没人在用就不查。（403 和 401 行为是实测，时间数字是设计取舍）
- 离职和冻结要更快，就用推送：一条集成平台工作流在名单变化时给各项目的一个公网接口发 `{"revision": N}`，项目回 202，再自己去拉整份名单。链路上没有要保管的凭证。实测从停用到踢掉会话约 1 秒。
  - 提醒接口要公网可达，不能挡在登录中间件后面。集成平台的 HTTP 节点不带凭证，假提醒最多让项目多拉一次。
  - 拉名单的地址用 IP 白名单保护。伪造 `X-Forwarded-For` 会被拒。（实测）
  - 名单 `complete` 不是 true 就保留旧名单。版本号比库里小的不写。从没同步成功过就拒绝所有登录。
  - 每次拉名单都算一次工作流运行，运行次数按月计费。每个实例限流，比如 30 秒最多一次，防止伪造提醒刷爆额度。
- 集成平台偶尔卡住，推送可能不到。要有定时对账兜底。

## 工作流做不了登录中心

触发地址由系统生成，不能用自己的域名。转进流程的请求头只有 10 个，不含 Cookie。返回头也只能设那 10 个，没有 Location 和 Set-Cookie。（文档）

## 还没验证的

- 加进禁止名单前签发、之后没刷新的 access_token，调用户信息是否也 403。
- 轮换前的旧 refresh_token 多久失效，撤销最新一枚会不会连带作废旧的。
- 在通讯录里真正停用账号后各项目是否一起被拒。
- 多维表格插件 iframe 里能不能登，用户信息接口的限流，控制台有没有强制下线。
