# 证据边界、勘误与待验证项

本文件说明哪里已经有依据，哪里仍不能作为 Computer Use 的确定性指令。资料日期：2026-09-21。

## 1. 证据级别

| 标记 | 意义 | 本项目中的例子 |
|---|---|---|
| 官方记载 | 在公开官方正文、参数说明或操作列表中采集到 | 表达式语法、操作名称、运行限制 |
| 界面观察 | 在浏览器中只读看到，并有截图／文本快照 | 模板节点名称、字段、版本和布局 |
| 实操验证 | 在允许范围内实际配置并运行，核对结果 | 本次为 0；不能用官方说明或截图冒充 |
| 整理建议 | 由已知语义归纳的使用方法 | 分页游标成功后推进、按来源核对引用 |
| 待验证 | 官方资料缺失、冲突或受当前界面限制 | 全部旧版本行为、真实导出文件结构 |

124 份组件手册覆盖公开目录；操作索引包含 2,467 个列表条目和 5 种正文定义的逻辑操作模式。该数量是检索条目数，不是去除跨连接器同名 API 后的独立底层接口数。

## 2. 已知文档问题及采用的解释

| 位置 | 原文问题 | 本手册的处理 |
|---|---|---|
| 分支／广播 | 示例写命中分支“并行执行”，另处写“从左到右依次执行” | 仅确认所有命中路径执行、无默认路径；不承诺路径完成顺序，也不依赖并发性 |
| 并行循环 | 字段叫“最大并行数量”，说明又写“每秒启动线程数” | 保留原措辞与最大 10；持续并发与启动速率的关系待实测 |
| 表达式数据类型 | 文字写六种，表中还包含 date | 逐项保留类型；不按“六种”排除 Date 能力 |
| `toNumber` | 调用规则误写 `toInteger` | 用方法名 `toNumber`；对照函数建议列表，不照抄错别字 |
| `parseDate` | 签名展示与包含时区的示例不一致 | 记录两个来源，不把可选参数数量当成已运行验证 |
| `durationDays` | 两个相同表达式示例给出相反结果 | 不以该示例判断符号方向；涉及天数差时先做一次已知日期验证 |
| 布尔值示例 | 出现 `fasle` | 有效布尔字面量写 `false` |
| 动态脚本 | TextEncoder／TextDecoder 的文字方向写反 | Encoder 将字符串编码为字节；Decoder 将字节解码为字符串；公开版保留纠正后的解释及原文链接 |
| 动态脚本正则示例 | `cont yearReg` | 这是语法错误；可用示例写 `const`，原文不当作可执行代码 |
| HTTP 响应编码 | 声称四种，实际列 UTF8、GB2312、GBK、GB18030、None 五项 | 按实际列表记录；以目标节点下拉框核对 |
| CSV 操作简介 | 分页读取与指定行读取的简短描述相互错配 | 按操作名称和详细参数判断用途，公开索引保留操作名并链接来源 |
| CSV 脚本示例 | `new Map()` 后用普通对象属性赋值 | 不把它当正确的 Map 写法；业务代码选择普通对象或 Map 的正确 API |
| 飞书消息 | 仍教在消息连接器创建群，当前目录已有飞书群组 | 优先使用当前操作列表与独立群组连接器 |
| 通用运行时长 | 旧简报写单节点 30 秒，当前限制页写 60 秒 | 通用值引用当前限制页；动态脚本仍按专用的 1 秒说明 |
| 凭证升级 | 历史示例中同版本连接器事件与动作适配不同凭证 | 不把版本分界推广成全平台定律；按具体操作的提示核对 |
| 模板 While | 最大次数预填 100 | 是模板值，官方上限为 1,000 |

对应来源见 [表达式速查](EXPRESSIONS.md)、[完整表达式参考](../reference/platform-using-expressions.md)、[版本与限制](VERSIONS_AND_LIMITS.md) 和各组件手册。

## 3. 尚未得到的证据

| 问题 | 当前已知 | 还缺什么 | 对后续操作的影响 |
|---|---|---|---|
| 所有组件的每个隐藏参数 | 本地已查阅公开正文和操作列表；开源版提供字段摘要和来源链接 | 其余操作的全部嵌套输入输出，以及凭证驱动的动态字段 | 第一次使用具体操作时需核对当前表单与真实出参 |
| 历史版本全集 | 当前文档版本号和少量明确版本差异 | 各旧版 schema、修订历史及迁移对照 | 不对未知旧版提供机械迁移步骤 |
| 拖拽与重排 | 官方编辑器步骤和只读画布样式 | 专属项目中实际拖入、移动、复制的结果 | 采用当前截图与落点反馈，不使用固定坐标 |
| 条件与循环全部边界 | 正文语义、限制和示例 | 广播调度次序、并行变量竞争、跨路径引用边界 | 不设计依赖未知顺序的流程 |
| 实际运行 | 官方机制与模板示意 | 一次真实调试／触发、输入输出、业务结果 | 当前配方属于待执行方案 |
| 原生导出 | 官方导入、复制、副本、模板等功能说明 | 真实导出入口、样例文件与完整导出 schema | 不编造可导入 JSON，不声称已读内置组件源码 |
| 内置组件实现源码 | 自建连接器映射、插件与脚本文档 | 平台内置组件的私有实现和运行引擎代码 | 操作说明不等于源码分析 |
| 所有节点样式 | 官方图标／图示地址；少数模板节点截图 | 每个版本、每种状态、每种操作的实际表单 | 不能声称完成全组件 UI 状态验证 |
| 官方图示 | 本地研究曾归档公开图示 | 开源副本不再分发第三方图示 | 按组件手册中的官方页面查看 |
| 平台维护状态 | 仍可访问官方文档及版本机制 | 官方停止维护／下线公告 | 不将“可能停更”写成事实 |

这是研究结果的适用范围，不是为现有授权增设审批。用户后续要求在专属项目搭建时，可按当时授权完成实施和必要验证；其他项目始终不得被借用作实验环境。

## 4. 后续最少补证顺序

1. 在 指定的练习项目 内，围绕第一条实际业务流程验证添加节点、引用胶囊、输入类型及一次运行。
2. 只展开并补齐这条流程所需操作的字段，记录连接器版本与实际出参。
3. 如果目标需要历史版本兼容、并行调度或导出，再针对该问题补证；不为了白皮书完整度运行无关业务动作。
4. 将结论写回相应组件手册及本文件，附截图或输入输出的必要证据；不保存凭证或业务敏感载荷。

每条记录应包括日期、项目／流程、节点操作与版本、输入条件、观察结果、证据路径。没有结果的计划保持“待验证”。
