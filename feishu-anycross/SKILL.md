# 飞书集成平台（AnyCross）

本技能把一个团队在真实租户里踩过的坑和一份 124 个组件的离线资料库合在一起。每条经验都标了证据等级。**实测**是真跑过并看到了结果。**文档**来自官方文档，没跑过。**推断**是从现象推出来的。给结论时沿用这三个标签，不要把文档或推断说成实测。

## 先守住这几条

1. **先只读。** 用户没明确同意前，不保存、不发布、不启用、不停用、不删除、不运行任何工作流。看运行日志和定义不用问。
2. **只动用户点名的项目和工作流。** 浏览器里开着别的工作流标签页，不代表可以动它。
3. **每改一处就验证一处**，顺序见 [改动流程](references/build-and-change.md#改动的固定循环)。换密钥放最后，它退不回去。
4. **会真的发消息、建群、写正式数据的流程不拿来试跑。** 等真实事件发生时盯着日志看，或在用户给的测试项目里复刻一份。
5. **密钥只由用户本人填。** App Secret、凭证、Basic 密码、服务器环境文件，AI 都不输入、不打印、不截图。网址触发器的回调地址也是密钥，不写进文档、代码、Git 和聊天。细节见 [密钥与安全](references/browser-automation.md#密钥与截图)。
6. **步骤显示成功不等于业务成功。** 去看下游返回的内容和运行日志。
7. **搭出来的东西要让没学过代码的人也看得懂。** 工作流的名称和描述、每个节点的显示名称、项目配置和数据存储都要写清楚它在做什么。节点不能停在「数据存储」「HTTP 请求」「手动触发器」这种默认名。别人打开就该看懂，不用再来问你。写法见 [备注怎么写](references/build-and-change.md#备注怎么写)。

资料库很大，不要整份读。用 `rg` 搜：

```sh
rg -n '发送卡片消息|创建记录|pageToken' references/guide/OPERATIONS.md references/guide/manuals
rg -n 'parseDate|toNumber' references/guide/reference/platform-using-expressions.md
```

组件手册的文件名是组件 ID，先在 [INDEX.md](references/guide/INDEX.md) 按名字查到 ID。资料快照是 2026-09-21，平台在更新，和当前界面冲突时以界面为准，并查 [勘误](references/guide/guides/EVIDENCE_GAPS.md)。官方文档本身有错（例如把 `toNumber` 写成 `toInteger`），不要照抄。

## 最容易栽的十个坑

1. 集成平台要用户已登录的浏览器。内置浏览器一般没登录，先问用户用哪个浏览器。（实测）
2. 读页面别用取正文的工具，拿到的是一堆 CSS。在页面里用 JS 调页面自己的只读接口，见 [盘点接口](references/inspect-and-debug.md#页面自己的只读接口)。（实测）
3. 从白名单以外的 IP 调回调地址，返回 403。换参数没用，先换到白名单里的机器上调。（实测）
4. 分支条件写成「整个 body 等于 prod」时，请求体必须就是 JSON 字符串 `"prod"`，带 `Content-Type: application/json`。发 `{"env":"prod"}` 会悄悄落进默认分支，拿回测试环境的结果。（实测）
5. 异步网址触发器收到请求就回 200，不代表流程跑过。要看运行日志。（实测）
6. 项目变量里叫「加密文本」的配置项只是名字，值是明文。HTTP 节点的凭证也换不了飞书 token。要飞书 token 就用自建连接器加「飞书应用身份认证」。（实测）
7. 草稿里可能积着很久没发布的旧改动。改草稿再发布，会把它们一起带上线。发布前先比草稿和线上版本。（草稿积压是实测，一起上线是推断）
8. 运行日志实际只留约 32 天。按流程汇总运行和失败次数，是找死流程最快的办法。（实测）
9. 同一个飞书应用的事件只能交给一个接收方。服务端已经用长连接收事件，集成平台上同一应用的事件触发器就会收不到。（文档加推断）
10. SSO 判断一个人有没有被禁，只能看用户信息接口返回 403。刷新照样成功。（实测）
